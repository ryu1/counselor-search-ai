# プロダクト要件書：カウンセラー検索AIデモ

## 1. プロダクトビジョン

自然言語で相談希望を入力するだけで、AIが条件を理解・整理し、条件に合致するカウンセリングオフィスを検索・提示するデモシステムを提供する。

**「検索条件をフォームで指定する」から「自然言語で相談する」への体験転換を実証する。**

---

## 2. ターゲットユーザー

| ユーザー | 説明 |
|---------|------|
| カウンセリングを検討中の一般ユーザー | 専門用語を知らない、どんな条件で探せばよいかわからない層。何らかの問題・悩み・課題を抱えており、自分一人では解決しにくいと感じている。誰かに相談したいと思っているが、どこに相談すればよいか、どのようなカウンセラーが自分に合うのか分からない。自分の悩みや希望をもとに、安心して相談できるカウンセラーを探すためにサイトを訪れる |
| デモ評価者（社内ステークホルダー） | 技術的実現性・UX・拡張性を判断する層 |

---

## 3. 解決したい課題・ニーズ

| 課題 | 現状 | 本デモでの解決 |
|------|------|----------------|
| 条件指定のハードルが高い | 駅・曜日・時間・方法・性別等をフォームで個別指定 | 自然言語一発で完結 |
| 日時表現が柔軟に使えない | 「明日」「来週土曜日」「9/12」「14時ごろ」等非対応 | 相対/絶対/曖昧表現を正規化して検索 |
| 検索条件の組み合わせが複雑 | AND/ORの挙動が不明確 | 同一項目OR・項目間ANDを明文化 |
| カウンセラー個人の空き枠が見えない | オフィス営業時間のみで判定 | 「営業時間内」までを検索し、予約可否は非スコープとして明示 |

---

## 4. 主要機能一覧

| ID | 機能 | 概要 |
|----|------|------|
| F-01 | 自然言語チャット入力 | Vue.js製チャットUIから自由文で相談希望を入力 |
| F-02 | 条件抽出・正規化 | Bedrock LLMが自然言語から構造化検索条件を抽出 |
| F-03 | マスター値正規化 | 駅名・専門領域・方法・性別・年代をマスター値へ変換 |
| F-04 | 日時解釈・正規化 | 「明日」「土曜14時ごろ」「9/12 10時」等をISO 8601/曜日指定へ変換 |
| F-05 | 条件不足時の追加質問 | 必須条件（方法等）不足時にのみ質問、既知条件は再質問しない |
| F-06 | 検索Tool呼び出し | 正規化済み条件で `search_counselors` Toolを実行 |
| F-07 | Athena SQL検索 | Lambdaが条件からSQL生成→Athena実行→結果集約 |
| F-08 | オフィス単位結果返却 | マッチしたカウンセラーを含むオフィスリストを返却 |
| F-09 | 結果の自然言語説明 | 検索結果をユーザー向けに要約・説明 |
| F-10 | 0件時の代替提案確認 | 条件緩和はユーザー確認の上でのみ実施 |

## 5. ビジネス要件

| 要件 | 内容 |
|------|------|
| 対象データ | 14オフィス・カウンセラー多数（S3 JSONL） |
| 検索対象 | オフィス営業時間ベース（カウンセラー個人の予約枠は非対象） |
| 公開範囲 | 社内デモ用（認証なし・パブリックアクセス可） |
| 環境 | 既存AWSアカウント・まっさらな状態・東京リージョン |
| インフラ | CloudFormationでIaC化・デモ終了後スタック削除でクリーンアップ |

## 6. ユーザーストーリー・受け入れ条件

### US-01: 駅・性別・方法・日時を自然言語で検索
**As a** ユーザー  
**I want to** 「新宿駅から近くて、女性のカウンセラーにオンラインで土曜日の14時ごろ相談したい」と入力する  
**So that** 条件に合致するオフィスが表示される

**受け入れ条件:**
- [ ] 「新宿駅」「女性」「オンライン」「土曜14時ごろ」が正しく抽出される
- [ ] 土曜日に営業し、13:00-15:00を営業時間内に含むオフィスが検索される
- [ ] 女性かつオンライン対応のカウンセラーが在籍するオフィスのみ表示される
- [ ] 同一カウンセラーが全条件を満たすこと（別カウンセラーの組み合わせではない）

### US-02: 相対日時表現で検索
**As a** ユーザー  
**I want to** 「明日の14時に相談したい」と入力する  
**So that** 翌日の14:00-15:00に営業しているオフィスが検索される

**受け入れ条件:**
- [ ] 実行時の現在日時（Asia/Tokyo）を基準に「明日」が解決される
- [ ] 該当曜日の営業時間と照合される

### US-03: 絶対日時表現で検索
**As a** ユーザー  
**I want to** 「9/12の10時に相談したい」と入力する  
**So that** 2026-09-12 10:00-11:00に営業しているオフィスが検索される

**受け入れ条件:**
- [ ] 年を補完してISO 8601に正規化される
- [ ] 該当日（土曜日）の営業時間と照合される

### US-04: 条件不足時に追加質問
**As a** ユーザー  
**I want to** 「不安について相談したい」とだけ入力する  
**So that** 「対面/オンライン/電話/チャットのどちらが希望ですか？」と質問される

**受け入れ条件:**
- [ ] 方法（method）が未指定の場合のみ質問される
- [ ] 既に会話で出た条件（駅等）は再質問されない

### US-05: 0件時は条件緩和を確認
**As a** ユーザー  
**I want to** 条件に合うオフィスが0件の場合  
**So that** 「該当なし。土曜日以外も含めますか？」等と確認される

**受け入れ条件:**
- [ ] AIが勝手に条件を緩和しない
- [ ] ユーザー確認の上でのみ条件変更する

## 7. 機能要件・非機能要件

### 機能要件

| ID | 要件 | 優先度 |
|----|------|--------|
| FR-01 | Vue.js製チャットUIでメッセージ送受信 | Must |
| FR-02 | AgentCore Runtime上でAgent実行 | Must |
| FR-03 | Bedrock（Claude 3.5 Sonnet/Haiku）で自然言語理解 | Must |
| FR-04 | `search_counselors` Tool実装（Lambda + Athena） | Must |
| FR-05 | S3 JSONLデータをGlue/Athenaで検索可能にする | Must |
| FR-06 | 検索条件：stations, area_of_expertise, methods, genders, ages, requested_datetime | Must |
| FR-07 | 同一項目OR・項目間ANDの検索ロジック | Must |
| FR-08 | オフィス単位集約・matched_counselors含む結果返却 | Must |
| FR-07 | CloudFormationで全リソース管理 | Must |

### 非機能要件

| ID | 要件 | 目標値 |
|----|------|--------|
| NFR-01 | チャット応答時間（検索込み） | < 10秒 |
| NFR-02 | 同時接続数（デモ想定） | 10ユーザー程度 |
| NFR-03 | 可用性 | デモ期間中99%以上 |
| NFR-04 | コスト（月額・デモ規模） | < $50/月 |
| NFR-05 | デプロイ時間 | < 15分 |
| NFR-06 | クリーンアップ | スタック削除で全リソース削除 |

## 8. 成功の定義

| 指標 | 成功基準 |
|------|----------|
| 機能完成度 | US-01〜US-05の全受け入れ条件を満たす |
| UX | 自然言語入力→結果表示まで会話が途切れない |
| 技術検証 | AgentCore + Bedrock + Lambda + Athenaの連携が安定動作 |

| ドキュメント | 設計書・実装計画・運用手順が揃い、第三者が再現可能 |
